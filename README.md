# Iran Build Expo

سامانهٔ مدیریت و معرفی نمایشگاه‌های Iran Build Expo؛ مخزن محصول مستقل از مخزن mainstructure.

**وضعیت:** اسکلت اولیه و مستندات طراحی؛ هنوز محصول کامل یا آمادهٔ انتشار نیست.

## تصمیم‌های قطعی نسخهٔ پایلوت

- **Backend و رندر عمومی:** Laravel + Blade؛ هیچ React یا SPA در پایلوت نداریم.
- **SEO:** صفحات عمومی از سمت سرور با HTML کامل رندر می‌شوند. SEO از ابتدا بخشی از طراحی و تست است.
- **زبان‌ها:** فارسی و انگلیسی با URL مستقل (`/fa/...` و `/en/...`).
- **پایگاه داده:** رابطه‌ای؛ MySQL/MariaDB گزینهٔ هدف اولیه است، اما پیش از اولین migration باید نسخه و امکانات محیط اجرا تأیید شود.
- **پرداخت آنلاین:** در v1 پیاده‌سازی نمی‌شود؛ پیش‌فاکتور معادل پرداخت یا تسویه نیست.
- **استقرار:** هنوز به تأیید نسخهٔ PHP، افزونه‌ها، دسترسی Composer/SSH، پایگاه داده، Cron و محدودیت‌های هاست نیاز دارد.

## پیش‌نیاز نسخهٔ فناوری

خط مبنای پیشنهادی این مخزن Laravel 13 و PHP 8.3+ است. طبق مستندات رسمی Laravel 13، PHP 8.3 یا بالاتر لازم است؛ قبل از انتخاب هاست، این شرط و افزونه‌های مورد نیاز را با ارائه‌دهنده تأیید کن: <https://laravel.com/docs/13.x/deployment>.

## نصب محلی پس از دریافت مخزن

این مخزن شامل `composer.json` و اسکلت آغازین Laravel است، نه پوشهٔ وابستگی‌های `vendor/` و نه `composer.lock`. پس از دریافت مخزن و داشتن PHP/Composer سازگار:

```bash
composer install
cp .env.example .env
php artisan key:generate
```

سپس مقادیر `.env` را تنظیم کن و اجرا کن:

```bash
php artisan serve
```

سایت در آدرس محلی‌ای که Artisan نشان می‌دهد قابل مشاهده خواهد بود. برای تست:

```bash
php artisan test
```

**محدودیت فعلی:** در محیط ساخت این بسته Composer در دسترس نبود و اتصال اینترنت هم برای دریافت dependencyها وجود نداشت؛ بنابراین نصب `vendor/`، اجرای تست‌های Laravel و بررسی runtime انجام نشده است. فقط صحت نحوی فایل‌های PHP و JSON قابل بررسی است. اولین کار بعد از انتقال به محیط توسعه، اجرای دستورات بالا و رفع هر خطای واقعی نصب است.

## ساختار مهم مخزن

- `app/`: کد PHP برنامه، کنترلرهای عمومی و middlewareهای پایه.
- `routes/web.php`: مسیرهای عمومی اولیه و مسیرهای SEO.
- `resources/views/`: قالب‌های Blade.
- `lang/`: متن‌های فارسی/انگلیسی.
- `docs/`: نیازمندی‌ها، معماری، SEO، امنیت، تست، عملیات و برنامهٔ اجرا.
- `tests/`: تست‌های اولیهٔ صفحات عمومی و SEO.
- `.github/workflows/ci.yml`: کنترل خودکار syntax، نصب وابستگی و تست در GitHub Actions.

## ترتیب کار

1. اطلاعات هاست و PHP را بررسی کن؛ تا آن موقع روی هاست فعلی Deploy نکن.
2. نیازمندی‌ها و تصمیم‌های باز را مرور و تأیید کن.
3. اولین برش قابل اجرا را کامل کن: locale، layout، SEO پایه و CI.
4. بعد مدل داده و migrationها را تأیید کن؛ پیش از تأیید قواعد کسب‌وکار، جدول‌های نهایی تولید نکن.
5. قابلیت‌ها را به‌صورت عمودی، همراه با تست و کنترل امنیت پیاده‌سازی کن.

## اصول غیرقابل‌مذاکره

- مجوزدهی باید سمت سرور و پیش‌فرض آن عدم دسترسی باشد.
- جداسازی اطلاعات شرکت‌ها باید در هر query، عملیات، خروجی و دسترسی فایل رعایت شود.
- تخصیص غرفه نیازمند transaction و جلوگیری دیتابیسی از تخصیص هم‌زمان است.
- OTP، سشن و توکن QR نباید در log ثبت شوند؛ QR نباید اطلاعات شخصی را افشا کند.
- هیچ CMSای نباید HTML/JavaScript دلخواه را بدون پالایش allowlist اجرا کند.
- مبالغ مالی نباید با `float` نگهداری یا محاسبه شوند.
- در محیط غیر production باید صفحات از ایندکس‌شدن منع شوند.
- ادعای موفقیت تست یا انتشار تنها با خروجی واقعی ابزارها مجاز است.

## اتصال به Engineering Framework

چارچوب مادر مرجع استانداردهاست، نه وابستگی runtime. این مخزن نسخهٔ چارچوب مورد استفاده را در `docs/08-decisions/framework-adoption.md` ثبت می‌کند. تغییرات چارچوب به‌صورت خودکار به این پروژه اعمال نمی‌شوند؛ فقط تغییر مرتبط پس از بررسی و برنامه‌ریزی وارد می‌شود.
