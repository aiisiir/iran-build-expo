# مدل دامنهٔ اولیه

این فهرست برای تحلیل و طراحی است، نه تأیید نهایی schema. روابط، کلیدها، حذف/آرشیو، مالکیت و قیود یکتا باید پیش از migrationها بررسی شوند.

| مفهوم | مسئولیت | نکتهٔ مهم |
|---|---|---|
| `ExhibitionEdition` | یک دورهٔ نمایشگاه | وضعیت انتشار و چرخهٔ عمر مشخص |
| `Venue` / `Hall` | محل و سالن‌ها | هر سالن در دوره/محل تعریف‌شده |
| `Booth` | غرفه | شناسهٔ پایدار، موقعیت روی نقشه و وضعیت |
| `BoothAllocation` | درخواست/تخصیص غرفه | transaction-safe و تاریخچه‌دار؛ یکتایی تخصیص فعال |
| `Company` | شرکت مشارکت‌کننده | مالک محتوای شرکت و مرز tenant |
| `CompanyUser` | اتصال کاربر به شرکت | نقش و وضعیت عضویت |
| `Product` / `Catalog` | محصولات و کاتالوگ | انتشار، slug و زبان/ترجمه |
| `Visitor` | هویت بازدیدکننده | کمینه‌سازی و حفاظت دادهٔ شخصی |
| `VisitRegistration` | ثبت‌نام برای دوره | وضعیت، زمان و شناسهٔ دوره |
| `CheckIn` | رویداد ورود | یکتایی/idempotency و لاگ بدون PII غیرضروری |
| `Lead` | درخواست تجاری | شرکت مقصد، رضایت/مبنای تماس و وضعیت |
| `SponsorPackage` / `Sponsorship` | بسته و توافق حمایت | وضعیت تأیید و انتشار |
| `Proforma` / `ProformaLine` | پیش‌فاکتور و ردیف‌ها | جدا از پرداخت؛ مبلغ دقیق |
| `CmsPage` / `ContentTranslation` | محتوا و ترجمه | وضعیت انتشار مستقل زبان، canonical و SEO metadata |
| `ContentRevision` | تاریخچهٔ محتوا | نویسنده، زمان و نسخهٔ قبلی |
| `MediaAsset` | رسانه | نوع، مالک، مجوز استفاده و نسخهٔ بهینه‌شده |
| `User` / `Role` / `Permission` | هویت و مجوز | اصل کمترین دسترسی و ثبت تغییر نقش |
| `AuditEvent` | رویداد ممیزی | بدون secrets و payload حساس غیرضروری |

## قواعد دامنه‌ای حیاتی

1. شرکت A نباید رکورد، فایل یا سرنخ شرکت B را با تغییر شناسه دسترسی داشته باشد.
2. تخصیص فعال هر غرفه/دوره باید از نظر دیتابیس و transaction غیرقابل‌تکرار باشد.
3. check-in برای یک registration باید idempotent باشد و اسکن تکراری وضعیت ثبت‌شده را تخریب نکند.
4. QR شامل PII نیست؛ توکن تصادفی غیرقابل‌حدس و ترجیحاً فقط hash آن ذخیره می‌شود.
5. پیش‌فاکتور هیچ اثر خودکاری بر دریافت پول ندارد.
6. محتوای CMS تنها پس از انتشار مجاز همان زبان قابل دسترسی عمومی و ایندکس است.
7. حذف و آرشیو داده‌ها باید با audit، حفظ سوابق ضروری و سیاست نگهداری هماهنگ باشد.
