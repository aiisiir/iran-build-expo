# نمای معماری پایلوت

## استک مصوب برای پایلوت

- **Laravel 13 + Blade** برای route، منطق برنامه و تولید HTML.
- **PHP 8.3+** به‌عنوان خط مبنای فنی؛ با هاست اشتراکی فعلی هنوز تطبیق داده نشده است.
- **MySQL/MariaDB** گزینهٔ هدف برای DB رابطه‌ای؛ نسخه/charset/backup/connection limit پس از بررسی هاست تثبیت می‌شود.
- CSS سبک و JavaScript محدود برای تعاملاتی که واقعاً لازم‌اند؛ React/SPA در محدودهٔ پایلوت نیست.
- ارائه‌دهندهٔ SMS، پیکربندی و روش صف/زمان‌بندی تا قبل از پیاده‌سازی OTP باید انتخاب و مستند شود.

## مرزهای منطقی ماژول

1. **Public Website + SEO:** صفحهٔ اصلی، دوره‌ها، شرکت‌ها، محصولات، اخبار، مسیرهای زبان، metadata، sitemap و robots.
2. **CMS and Editions:** صفحات، نسخه‌ها، جریان انتشار و مدیریت دوره‌ها.
3. **Company & Catalog:** شرکت‌ها، کاربران وابسته، محصولات، کاتالوگ و رسانه‌ها.
4. **Venue & Booths:** سالن، نقشه، غرفه، درخواست، تخصیص و تاریخچه.
5. **Visitor & Check-in:** ثبت‌نام، OTP، QR، پذیرش و ثبت ورود.
6. **B2B Leads:** درخواست ارتباط و مدیریت سرنخ‌ها با جداسازی شرکت.
7. **Sponsorship & Proformas:** بسته‌ها، جایگاه‌ها، تعهدها و پیش‌فاکتور؛ بدون دریافت پول در v1.
8. **Administration, Reports & Audit:** کاربران، نقش‌ها، خروجی‌ها، گزارش و لاگ ممیزی.

این‌ها مرزهای مفهومی‌اند، نه الزام به ساختن 8 سرویس یا 8 پکیج جدا. در پایلوت یک Laravel monolith ماژولار کم‌پیچیدگی انتخاب شده است.

## اصول معماری
- authorization و tenant isolation در سمت سرور.
- schema رابطه‌ای و قیود دیتابیس برای invariants مهم؛ اعتبارسنجی PHP جای قید دیتابیس را نمی‌گیرد.
- عملیات چندمرحله‌ای مانند تخصیص غرفه داخل transaction.
- سرویس‌های بیرونی مثل SMS پشت interface مشخص قرار گیرند تا provider قابل تعویض باشد.
- هر ماژول در حد نیاز فعلی طراحی شود؛ از microservice، event bus یا پیچیدگی توزیع‌شده بدون توجیه اجتناب شود.
- منطق SEO در helper/view component مشترک بماند، ولی داده و سیاست هر نوع صفحه explicit باشد.

## SEO و رندر
Blade HTML اولیه را تولید می‌کند. برای هر صفحهٔ indexable title، description، canonical، hreflang، robots و داده‌های اجتماعی از منبع معتبر تولید می‌شود. Sitemap باید از رکوردهای منتشرشدهٔ واقعی ساخته شود؛ نسخهٔ اولیهٔ مخزن تنها home فارسی/انگلیسی را برای آزمایش قالب معرفی می‌کند.

## تصمیم‌هایی که قبل از migration لازم‌اند
- مدل دادهٔ نهایی و ownership هر موجودیت.
- قواعد پول/ارز/تخفیف/مالیات و وضعیت پیش‌فاکتور.
- نقش‌ها و مجوزها.
- چرخهٔ عمر دوره، شرکت، محصول، محتوا و غرفه.
- سیاست نگهداری داده و رضایت تماس.
- هاست، DB، SMS، Cron، queue و عملیات backup/restore.
