# معیارهای پذیرش سطح بالا

این‌ها در سطح محصول‌اند؛ هر آیتم باید بعداً به تست Feature، Unit، Integration یا تست دستی قابل تکرار متصل شود.

| ID | معیار پذیرش | شواهد لازم |
|---|---|---|
| AC-SEO-001 | عنوان، توضیحات و محتوای اصلی صفحهٔ عمومی در HTML اولیه وجود دارد. | تست HTTP/HTML و بررسی خروجی نهایی |
| AC-SEO-002 | صفحهٔ فارسی و معادل انگلیسی URL و canonical مستقل دارند. | تست `canonical` و `hreflang` متقابل |
| AC-SEO-003 | draft، صفحات خصوصی، پنل و داده‌های شخصی در sitemap نیستند. | تست sitemap با داده‌های وضعیت متفاوت |
| AC-SEO-004 | محیط غیر production دارای `noindex` است و sitemap عمومی نمی‌شود. | تست middleware و مسیر sitemap |
| AC-SEC-001 | کاربر شرکت A نمی‌تواند با تغییر ID رکورد شرکت B را بخواند یا تغییر دهد. | تست مجوز برای show/update/export/download |
| AC-BOOTH-001 | دو درخواست هم‌زمان برای یک غرفه به دو تخصیص قطعی منجر نمی‌شود. | تست هم‌زمانی روی DB هدف، نه فقط SQLite |
| AC-OTP-001 | OTP منقضی یا بیش از حد تلاش‌شده رد می‌شود. | تست انقضا و rate-limit |
| AC-QR-001 | QR هیچ PII ندارد و اسکن تکراری check-in تکراری نمی‌سازد. | تست محتوای توکن و idempotency |
| AC-CMS-001 | محتوای draft منتشر نمی‌شود و HTML/JS ناامن اجرا نمی‌شود. | تست policy انتشار و sanitization |
| AC-FIN-001 | پیش‌فاکتور وضعیت پرداخت مستقل دارد و `float` در محاسبات مالی به‌کار نمی‌رود. | تست محاسبه و مدل وضعیت‌ها |
| AC-OPS-001 | بکاپ روی محیط جداگانه restore شده و نتیجه ثبت می‌شود. | گزارش واقعی آزمون بازیابی |
| AC-A11Y-001 | مسیرهای اصلی با صفحه‌کلید قابل انجام هستند و label/heading معنایی دارند. | تست خودکار به‌علاوه بازبینی دستی |

## افزوده‌های ۲۰۲۶-۱۰-۲۸

| ID | معیار پذیرش | شواهد لازم |
|---|---|---|
| AC-BOOTH-002 | یک شرکت نمی‌تواند در یک دوره دو غرفهٔ فعال (رزرو/قطعی) داشته باشد، حتی با دو درخواست هم‌زمان. | تست هم‌زمانی روی MariaDB |
| AC-BOOTH-003 | رزرو پس از ۳ ساعت بدون cron آزاد حساب می‌شود و دیگری می‌تواند همان غرفه را رزرو کند. | تست با زمان مجازی (Carbon::setTestNow) |
| AC-FIN-002 | مبالغ عدد صحیح ریال‌اند و هیچ ستون/محاسبه‌ای از float استفاده نمی‌کند. | بازبینی schema + تست |
| AC-QR-002 | ناهار برای یک کارت در یک روز دوبار ثبت نمی‌شود (حتی هم‌زمان). | تست قید یکتا و هم‌زمانی |
| AC-QR-003 | کارت باطل‌شده اسکن‌پذیر نیست و اسکن رد ثبت می‌شود. | تست |
| AC-I18N-001 | تبدیل میلادی↔جلالی برای تاریخ‌های مرجع (مثلاً 2025-03-21 = 1404/01/01) درست است. | تست واحد |
| AC-DEP-001 | صفحهٔ تست استقرار روی ساب‌دامین با SSL و PHP 8.4 باز می‌شود و `check.php` پس از استفاده حذف شده است. | خروجی واقعی check.php از مالک |
