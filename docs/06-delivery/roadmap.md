# نقشهٔ اجرای پایلوت

## مرحلهٔ 0 — آماده‌سازی و اثبات امکان اجرا
- [ ] تأیید نسخهٔ PHP، Composer/SSH، افزونه‌ها، DB، Cron، دسترسی فایل و backup در هاست.
- [ ] اجرای `composer install` در محیط توسعه و ایجاد/ثبت `composer.lock`.
- [ ] سبزشدن CI و تست‌های اولیه.
- [ ] تأیید domain، SSL و سیاست محیط staging/production.

## مرحلهٔ 1 — هسته و سایت عمومی
- [ ] نهایی‌کردن routeهای فارسی/انگلیسی، layout و navigation.
- [ ] پیاده‌سازی component مرکزی metadata و آزمون SEO.
- [ ] sitemap بر اساس رکوردهای منتشرشده؛ robots و noindex محیط‌ها.
- [ ] تعریف design tokens، accessibility و baseline performance.

## مرحلهٔ 2 — CMS و دوره‌ها
- [ ] تصویب مدل داده و migrationها.
- [ ] CMS با revision، draft/review/publish و publication مستقل زبان.
- [ ] مدیریت دوره‌ها و آرشیو؛ slug و redirect پایدار.
- [ ] تست مجوز، انتشار و SEO صفحات دوره.

## مرحلهٔ 3 — شرکت‌ها و محصولات
- [ ] کاربران شرکت و جداسازی tenant.
- [ ] پروفایل شرکت، محصول/کاتالوگ، رسانه و وضعیت انتشار.
- [ ] سیاست و تست canonical/metadata/sitemap برای صفحات شرکت و محصول.

## مرحلهٔ 4 — محل نمایشگاه و غرفه‌ها
- [ ] مدل سالن/غرفه و قراردادهای تخصیص.
- [ ] transaction/constraint برای جلوگیری از double booking.
- [ ] رابط نقشه با HTML قابل فهم و progressive enhancement.

## مرحلهٔ 5 — بازدیدکنندگان و پذیرش
- [ ] انتخاب provider پیامک و توافق نرخ/حریم خصوصی.
- [ ] OTP، rate limiting و audit بدون ثبت رازها.
- [ ] QR opaque و check-in idempotent.

## مرحلهٔ 6 — تعاملات تجاری و مالی
- [ ] B2B leads و tenant isolation.
- [ ] حمایت مالی/جایگاه تبلیغاتی.
- [ ] پیش‌فاکتور بدون پرداخت آنلاین؛ قواعد مالی تصویب‌شده.
- [ ] گزارش و خروجی امن.

## مرحلهٔ 7 — آماده‌سازی انتشار
- [ ] آزمون دسترسی و امنیت.
- [ ] تست عملکرد با دادهٔ واقع‌بینانه.
- [ ] بررسی SEO و Search Console.
- [ ] backup/restore، rollback و runbook.
- [ ] پذیرش نهایی توسط مالک محصول.

**اصل:** مراحل می‌توانند با شواهد کافی بازتنظیم شوند؛ featureهای بعدی را قبل از سبزشدن کنترل‌های ریسک بالا روی هم انباشته نکنیم.
